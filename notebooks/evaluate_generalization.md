# Model Evaluation & Generalization

This document covers evaluation results, feature importances, failure cases, and limitations for the three Random Forest models trained in this project.

## Training Setup

| Parameter | Value |
|---|---|
| Model type | Random Forest (scikit-learn) |
| `n_estimators` | 200 |
| `max_depth` | 12 |
| `class_weight` | balanced |
| Train/test split | 80% / 20% (stratified by quality_label) |
| Feature vector | 10-dim engineered CV features |
| Training data | Synthetically degraded images (see `degrade.py`) |

The dataset is generated by applying 6 degradation types at 3 severity levels to clean source images, plus untouched "clean" copies. Ground truth is exact because we created the degradation ourselves.

Scores are calibrated by the `make_labeled_sample()` function in `degrade.py`:
- `clean` images → score in `[88, 100]`
- Degraded images → `95 - severity_penalty + noise`, clipped to `[0, 95]`

- `noise`, `overexposure`, `underexposure` are near-perfect (F1 > 0.95) — these have strong unambiguous feature signals.

- `clean` has the lowest precision (0.65) — the model is sometimes conservatively over-cautious.
- `visual_defect` (F1 = 0.76) is the weakest class, expected given the heterogeneity of defects.

## Feature Importances

Feature importances from the quality label classifier
(`models/metrics.json → feature_importances`):

| Feature | Importance | Interpretation |
|---|---|---|
| `sharpness` | highest | Most discriminative — blurry images drop this dramatically |
| `noise` | high | Residual noise separates noisy from clean images |
| `mean_brightness` | high | Key signal for exposure issues |
| `dark_pixel_fraction` | medium | Underexposure indicator |
| `bright_pixel_fraction` | medium | Overexposure indicator |
| `contrast` | medium | Low contrast = washed-out / overexposed |
| `block_uniformity` | medium | Near-zero for all real images; jumps for corrupted files |
| `edge_density` | lower | Correlated with sharpness; helpful combined signal |
| `mean_saturation` | lower | Less discriminative for quality classification |
| `std_saturation` | lower | Low individual importance |

> Note: Importances are relative and sum to 1. Run `GET /metrics` to see live values.

## Known Failure Cases

### 1. Blur vs. Underexposure Confusion
**Problem:** Very dark, sharp images (e.g. night scenes with rich texture) may be misclassified as blurry because low brightness reduces the Laplacian variance even when edges are sharp.

**Mitigation:** The multi-feature approach partially handles this — the `mean_brightness` feature should distinguish underexposure from blur. But the overlap is real and the confusion matrix may show some off-diagonal errors here.

### 2. Synthetic vs. Real Noise Distribution
**Problem:** The synthetic Gaussian noise (via `apply_noise()`) has a specific distribution. Real camera sensor noise (shot noise, read noise, fixed-pattern noise) has a different statistical structure.

**Impact:** The model may under-detect moderate real-world noise while correctly detecting synthetic Gaussian noise at the same sigma level.

### 3. Visual Defect Generalization
**Problem:** `visual_defect` is trained on scratch lines + tinted regions (lens flare / watermark simulations). Real visual defects — dead sensor pixels, lens chromatic aberration, physical scratches on a phone camera — may not trigger this class reliably.

**Impact:** This is the hardest class to generalize because "visual defect" is an open-ended category.

### 4. Compression Artifacts vs. Corruption
**Problem:** Heavily JPEG-compressed images (low quality factor) share some features with "corrupted" images — both have blocky artifacts and reduced edge density. The classifier may flag heavily compressed legitimate images as `corruption`.

### 5. Intentionally Minimal Images
**Problem:** A pure white image, a test pattern, or a solid color swatch will produce extreme feature values (sharpness = 0, block_uniformity = 1, etc.) that the model was not trained on, potentially producing arbitrary predictions.

## Generalization Discussion

**Training distribution:** All training images are generated by applying `degrade.py` transforms to clean source photos. The training set is 100% synthetic — ground truth is exactly known but the image content is limited to whichever clean photos were in `data/raw/`.

**Potential domain gap:** 
- The model generalizes well to new images *of the same degradation type* since the features capture the physics of each degradation mathematically.
- The model may generalize less well to degradation that looks different from the synthetic versions — particularly real noise (see Failure Case 2) and real visual defects (Failure Case 3).

**What works well on real images:**
- Blur detection: sharpness (Laplacian variance) is a robust, well-established signal.
- Underexposure / overexposure: brightness stats are pixel-level and agnostic to image content.
- Corruption: block_uniformity is a hard structural signal that works exactly the same for real JPEG truncation.

**Honest limitations:**
- No real-image evaluation set (would require manual labeling of degraded real photos).
- The 10-feature approach cannot capture spatially localized issues (e.g., blur only in one corner while the rest is sharp).
- There is no uncertainty calibration — confidence values from `predict_proba()` are the raw RF posterior estimates, which tend to be overconfident.

---

## Improvement Directions

| Area | Possible Improvement |
|---|---|
| Real noise | Train on a dataset with real camera noise (e.g. SIDD, DND) |
| Visual defects | Use an anomaly-detection approach (one-class SVM or autoencoder) instead of a supervised class |
| Spatial localization | Add per-region feature extraction for localized blur/noise heatmaps |
| Calibration | Apply Platt scaling or isotonic regression to calibrate `predict_proba()` |
| More features | Add frequency-domain features (FFT magnitude) or BRISQUE-style local variance |
